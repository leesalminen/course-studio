# Course Studio repository guidance

## When the user wants to use or set up a course

Read `docs/CHATGPT-WORK-SETUP.md` and follow it, then use `skills/course-studio/SKILL.md`. Handle supported setup steps and begin the guided parent interview. Use the supplied quick-start details when present. Do not turn a parent setup request into repository development or rebuild the sample PDFs first.

## When the user wants to maintain this repository

- Preserve the distinction between current-session use and verified persistent installation.
- Canonical skill instructions live in `skills/course-studio/`; `chatgpt/COURSE-STUDIO-PROMPT.md` is the standalone adaptation and must retain the same essential behavior.
- `chatgpt/COURSE-STUDIO-HANDBOOK.md`, `chatgpt/START-COURSE-STUDIO.md`, root `manifest.json`, and `Course-Studio-Starter-Kit.zip` are generated by `python3 scripts/package.py`. Edit their sources, then regenerate them.
- Read `docs/MAINTAINING.md` before changing packaging or sample production. Run `python3 scripts/package.py --check` after changes. PDF changes require rendering and visual inspection of affected pages.
- Keep family course output in ignored `courses/` or another task-owned directory. Never add child profiles, private chats, tokens, local environments, or QA page images to public files.
- Reuse existing tools and dependencies. Do not modify unrelated global configuration or install plugins as an incidental repository maintenance step.
